# 사용자에게 보이는 줄(📝 한 줄 · 표 머리)은 워크스페이스 언어를 따른다.

## logviser 를 부른 턴 (스킬용)
LOGVISER — 이번 턴 logviser 스킬용 표 (프로젝트마다 log.md 로 아직 안 옮긴 trace).
이번 턴 전 .alfred/logviser 상태: <on | lite | off>
<표>

## 하루 끝 (켜져 있을 때, 프롬프트에 "퇴근" · "오늘 끝" · "하루 마무리" · "wrap up the day" · "done for the day" · "call it a day" 등)
LOGVISER — 하루 끝. 아래는 trace 를 log.md 로 다 옮기지 않은 프로젝트다.
**이 답 끝에 표를 그대로 보여 주고, 저장할지 사용자에게 묻는다** (워크스페이스 언어로). 표만 — 무엇을 저장할지 제안하지 않는다.
<표>

## lite
LOGVISER (lite) — log.md 로 옮기지 않은 trace 가 임계를 넘은 프로젝트가 있다.
**이 답 맨 끝에 아래 줄을 프로젝트마다 그대로 붙인다.** 질문 창도, 저장하자는 제안도 없다 — 알리기만 한다.
📝 <code>: log 안 된 trace N건 (<code>-trace<a>~<b>)

## on
LOGVISER — log.md 로 옮기지 않은 trace 가 임계를 넘은 프로젝트가 있다.
**이 턴에 사용자 요청을 먼저 처리하고, 끝에 질문 창(AskUserQuestion) 하나를 띄운다.**
- <code>: 미저장 N건 — <code>-trace<a>~<b> (임계 T). trace 파일: project-logs/<dir>/trace/

창 만드는 법 (프로젝트마다 질문 하나, 최대 4개), 워크스페이스 언어로:
1. 그 범위의 trace 헤더(`## <code>-trace<N> HH:MM — 제목`)를 읽고 질문을 이렇게 쓴다:
   "지금까지 <code> 에서 <trace 제목들을 2~3 개로 묶은 요약> 을 진행하셨습니다 (trace N~M, K건).
    어떤 판단을 근거로, 또는 어떤 의도로 이 내용들을 진행하셨나요?"
   trace 에 적힌 사실만. 해석을 붙이지 않는다.
2. 선택지 둘: "지금 log 로 저장" / "스킵 — 임계만큼 더 쌓이면 다시 묻기".
   직접 입력 칸에 적은 것은 사용자의 판단 · 의도다 — 항목 Decision & Reason 의 재료로, 적힌 그대로 사용자 판단으로 표기해 쓴다.
   **직접 입력 칸에 판단을 적었으면 "지금 log 로 저장" 을 고른 것으로 본다.**
3. 저장이면 (직접 입력 포함): 같은 답 안에서 그 판단을 넣은 초안을 채팅에 보여 주고, 확정받은 뒤에만 쓴다.
   스킵이면 아무것도 쓰지 않는다. 같은 프로젝트는 trace 가 임계만큼 더 쌓인 뒤에만 다시 묻는다 (임계 8 → 8번째에 묻고, 스킵 → 16번째에 다시).
4. **사용자 요청에 대한 답은 창 뒤의 마지막 답에 전부 쓴다.** 사용자에게는 마지막 답만 보일 수 있다: 창 앞에 쓴 글은 창이 닫히면 접힌다.
   - 순서: (도구로 할 일) → 질문 창 → 답을 받은 뒤 **마지막 답 = 요청에 대한 답 전체**, 그 아래 창 결과 한 줄 (스킵, 또는 저장 초안)
   - 창 앞에는 답을 쓰지 않는다. "위에서 답했다" · 요약만 쓰기 금지 — 마지막 답만 읽어도 요청의 답이 다 있어야 한다
