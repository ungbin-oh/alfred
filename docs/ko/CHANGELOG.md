written by Ungbin_Oh · created 2026-10-03 · updated 2026-10-05

> **한국어 번역본이다.** 정본은 레포 루트의 `CHANGELOG.md` (영어). 정본이 바뀌면 같은 커밋에서 맞춘다.

최신이 위. 해시는 이 레포의 커밋. 0.1.8 부터 레포 전체에 버전이 하나다 — 두 플러그인(Claude Code 용 `alfred`, Codex 용 `alfred-codex`)이 같은 번호를 쓰고, 항목마다 **[Claude]** · **[Codex]** · **[공통]** 을 붙인다.

## 0.1.8 — 2026-10-05

**버그 수정.** 두 플러그인 모두 0.1.8.

- **[Codex] Codex 자체 `/init` 을 Alfred 설정으로 착각할 수 있었다** — Codex 는 시작 화면마다 `/init` 을 띄운다. 기여자 가이드
  `AGENTS.md` 를 쓰는 Codex 명령인데, Alfred 워크스페이스에서는 그 파일에 사용자 설정이 들어 있다.
  새 `UserPromptSubmit` 훅(`alfred-codex/hooks/init-guard.sh`)이 Alfred 워크스페이스에서 `/init` 프롬프트를 잡아,
  모델이 어떤 파일도 건드리지 않고 Alfred 는 이미 설정돼 있다고(`$alfred-init` 이 Alfred 설정) 안내하게 한다.
  Alfred 워크스페이스 밖에서는 `/init` 이 원래대로 된다. 업데이트 뒤 Codex 가 훅 신뢰를 한 번 더 묻는다

## 0.1.7 — 2026-10-05

**버그 수정** (두 플러그인 모두: `alfred` · `alfred-codex` 가 0.1.7).

- **`alfred-init`: 파일 목록을 질문 창이 가렸다** — 3단계가 만들 파일 목록을 보여 준 뒤 질문 창으로 확인받게 돼 있었다.
  창이 목록을 가렸고, 선택지 미리보기에 넣은 목록은 15줄 안팎에서 잘렸다. 규약의 질문 창 절과 어긋나 있었다.
  이제 목록은 채팅으로 보여 주고 채팅으로 확인받는다

## 0.1.6 — 2026-10-05

Codex 지원. 같은 레포 안에 플러그인을 따로 둔다.

- **레포 하나, 플러그인 둘** — `alfred-claude/` (Claude Code, 플러그인 `alfred`, 안쪽은 0.1.5 그대로) 와 `alfred-codex/`
  (Codex, 플러그인 `alfred-codex`, 0.1.6). 루트 마켓플레이스가 둘 다 싣는다. 공용 파일(규약 · 스킬 · 템플릿)은 양쪽에 복사한다.
  Claude Code 사용자는 전과 같이 `alfred@alfred` 로 설치한다
- **Codex: 규약은 세션 시작 훅으로** — `AGENTS.md` 에는 import 가 없어서 훅이 세션마다 규약 전문을 출력한다.
  `alfred-codex/hooks/hooks.json` 에서 출력 상한을 20,000 토큰으로 올렸다 (Codex 기본은 약 2,500 토큰, 넘으면 가운데를 자른다).
  훅은 `hooks/hooks.json` 에 둔다 — Codex 는 `plugin.json` 안에 적은 훅을 읽지 않는다
- **Codex: 설정은 `AGENTS.md`** — `alfred-init` 이 `templates/<lang>/AGENTS.md` 로 `AGENTS.md` 를 만든다. `.alfred/rules.md` 복사본 ·
  상태줄 배지는 없다 (Codex 는 사용자 상태줄이 없다). 질문 창은 켜져 있으면 `request_user_input`, 아니면 채팅
- **Codex: 훅을 한 번 신뢰** — Codex 는 플러그인 훅을 돌리기 전에 사용자에게 검토를 받는다

## 0.1.5 — 2026-10-05

Alfred 가 본뜬 워크스페이스의 규약 변경을 옮겨 왔다 (그쪽 규약을 절마다 읽히는 문장으로 다시 썼다). 레포에서 개인 정보를 뺐다.

- **문장을 풀어 썼고 규칙은 같다** — 역할 경계 · 제안 금지 · 실행 전 확인 · 질문 창을 누가 무엇을 하는지 온전한 문장으로. 규칙 도입 날짜는 원래 없었다
- **부팅 때 어제 `## To do` 를 한 번 묻는다** — 훑고, 브리핑에서 다 했는지 묻는다
- **질문 창** — 미리보기 칸은 써도 된다 (답하려면 전부 봐야 하는 긴 내용만 넣지 않는다). 사용자에게 마지막 답변만 보이면
  질문에 필요한 사실은 창 안에 넣고, 질문이 길면 채팅으로 묻는다
- **한 번에 한 프로젝트** — 다른 프로젝트의 기록 안 된 것은 말하지 않고 기억해 두었다가, 사용자가 프로젝트를 바꾸거나 "저장해" 할 때 꺼낸다
- **시각** — 초안을 먼저 보여 줘야 해서 셸이 시각을 채울 수 없을 때도 `date` 를 본다
- **log.md** — `aliases` 설명 추가 · 판단 주체에 `판단:` 을 붙이지 않음 · 미검증 추정치는 trace 로, 한 번 잰 측정값은 `docs/` 에 두지 않음 ·
  항목 번호는 0 을 채우지 않고 가장 최근 파일의 마지막 헤더로 다음 번호를 정함 (`sort` 경고 삭제) · 브리핑에 objective 를 보인다는 줄 삭제
- **trace** — 그 프로젝트에서 오간 것을 모두 남긴다: 질문 · 요청 · 답 · 시도 · 결정
- **open.md** — 따로 두는 이유는 log · trace · decision 과 성격이 다른 문서라서
- **decision.md** — 판단은 사용자가 고심해서 정한 진행 방향이고, **무엇이 판단인지는 사용자가 정한다.**
  "무엇이 판단인가" · "조각을 미리 적는다" 삭제. 따로 두는 이유: log 만으로는 판단이 잘 기록되지 않았다
- **Timeline** — 남길 막다른 길을 구체적으로 (판단을 흔든 틀린 추정, 근거로 쓸 뻔한 잘못 잰 수치, 통과했다고 했는데 아니었던 것). 도구 실수는 trace 에만
- **개인 정보 삭제** — `rules/core.md` 의 저작 줄 삭제 (모델이 읽는 파일이라 답에 샐 수 있다) · Timeline 예시의 "지도교수 미팅" → "팀 미팅"

## 0.1.4 — 2026-10-05

- **공통 규약을 훅 출력이 아니라 `CLAUDE.md` 로 불러온다.** Claude Code 는 훅 출력을 10,000자에서 자르는데 규약은 약 24,000자라,
  0.1.2 부터 모델에게는 2,000자 미리보기(0~1절)만 보였다. 이제 `hooks/sync-rules.sh` 가 `rules/core.md` 를 워크스페이스의
  `.alfred/rules.md` 로 복사하고, `CLAUDE.md` 가 `@.alfred/rules.md` 한 줄로 불러온다 (import 는 파일당 4 MiB 까지 통째로 들어간다).
  세션 시작 훅은 짧은 머리말만 찍고, 복사본이 다르면 새로 맞춘다. `/alfred-init` 이 복사본과 import 줄을 만든다

**기존 워크스페이스:** `CLAUDE.md` 는 세션 시작 훅보다 먼저 읽히므로, 훅이 방금 만들거나 고친 복사본은 다음 세션부터 저절로 들어간다.
그 첫 세션에서는 Alfred 가 파일을 직접 읽는다. 0.1.4 이전 워크스페이스에는 `@.alfred/rules.md` 줄이 없다 — Alfred 가 넣을지 한 번 묻고,
답 없이 `CLAUDE.md` 를 고치지 않는다.

## 0.1.3 — 2026-10-03

Alfred 가 본뜬 워크스페이스의 규약 변경을 옮겨 왔다.

- **open.md 닫힌 것 표** (c40fd39) — 결정된 항목을 지우지 않고 `## 닫힌 것` 표에 한 줄로 옮긴다
  (항목 · 닫힌 날 · 결론이 간 곳). 파일은 남고 남은 항목 번호는 그대로
- **Timeline 요약 표** (d3c99b0) — daily Timeline 맨 위에 표(# · 시각 · 프로젝트 · 한 줄), 그 아래 덩어리별 상세. 예시 두 벌 갱신
- **큰 구현이라고 별도 세션을 권하지 않는다** (e9f1396) — 기획과 구현을 한 세션에서
- **neglected 표시** (4a6a6d8) — 14일 넘게 손대지 않은 active 프로젝트는 브리핑에 `🔴 neglected`. 표시만, status 는 자동으로 바꾸지 않는다
- **Archive** (b8d667d) — `Archive/` 아래 `workspace-archive/`(산출물, git 제외) · `log-archive/`(기록, git 추적) · README 목록 표.
  새 status `archived`. 부팅·프로젝트 찾기는 보지 않는다. `/alfred-init` 이 만든다
- **규약 정리** (2d449c0) — 선택지는 이미 나온 것만, 브리핑 프로젝트 칸 `이름 (code)`,
  미정 next_action 은 "미정" (open.md 가 있으면 "미정 — [[open]] 참조"), 질문 창은 짧은 선택만 · 긴 초안은 채팅으로 확인
- **decision.md** (04efbb6) — 프로젝트의 방향을 정한 판단만 모아 목적과 비교하는 문서. `## 출발점` 으로 시작.
  채팅으로 한 번에 한 질문씩 인터뷰해서 쓴다

**기존 워크스페이스:** 규약은 플러그인과 함께 바뀐다. `Archive/` 와 새 `.gitignore` 줄은 `/alfred-init` 만 만들므로,
기존 워크스페이스에서 쓰려면 `Archive/README.md` 와 `.gitignore` 의 `Archive/workspace-archive/` 를 직접 추가한다.
기존 프로젝트의 `decision.md` 는 쓰기 시작할 때 만든다.
