# guide-mode

written by Ungbin_Oh · created 2026-10-06 · updated 2026-10-06

> **한국어 번역본이다.** 정본은 `alfred-claude/skills/guide-mode/SKILL.md` (영어) 이고 Claude Code 는 이 파일을 읽지 않는다.
> 정본이 바뀌면 이 파일도 같은 커밋에서 맞춘다. Codex 판(`alfred-codex/skills/guide-mode/SKILL.md`)은 호출 이름이 `$guide-mode`,
> 설정 파일이 `AGENTS.md`, 첫 질문을 `request_user_input` 으로(없으면 채팅 한 줄) 묻는다는 것만 다르다.

스킬 설명: 가이드 모드 토글 (on / off / status). 사용자가 /guide-mode 를 입력할 때만 쓴다. 켜면 Alfred 를 짧게 소개하고, 그 뒤로 가끔 짧은 사용법 팁을 준다.

Alfred 가 처음인 사람을 위한 모드다. 켜면 Alfred 를 짧게 소개하고 첫 사용을 이끈다. 켜져 있는 동안에는 가끔 짧은 사용법 팁을 붙인다.
상태는 워크스페이스의 `.alfred/guide-mode` 파일이고(있으면 켜짐), 플러그인의 UserPromptSubmit 훅이 매 턴 팁 규칙을 넣는다.

워크스페이스 루트 = 작업 폴더 또는 `.alfred/workspace` 가 있는 가장 가까운 상위 폴더.
없으면 "Alfred 워크스페이스가 아닙니다" 라고 하고 멈춘다.

워크스페이스 언어(`.alfred/workspace` 의 `language:`)로 말하고, 설정 파일(`CLAUDE.md`)의 호칭 · 비서 이름을 쓴다.

## 인자별 동작

| 인자 | 동작 |
|---|---|
| `on` (또는 꺼져 있을 때 인자 없음) | `.alfred/guide-mode` 를 만든다 (한 줄: `on`). 이어서 아래 소개 |
| `off` | `.alfred/guide-mode` 를 지운다. 꺼졌다는 것과 `/guide-mode on` 으로 다시 켠다는 것을 한 줄로 |
| `status` | 파일이 있으면 "켜짐", 없으면 "꺼짐" |
| (켜져 있을 때 인자 없음) | 이미 켜져 있고, `/guide-mode off` 로 끈다고 알린다 |
| 그 밖 | 모르는 인자라고 하고 사용법: `/guide-mode on \| off \| status` |

상태 파일을 만들고 지우는 것은 비서가 한다 (수동 모드가 켜져 있어도 허용).

## 소개 (켤 때)

짧게 — 열 줄 안팎, 항목마다 한 줄, 표 없이. 쉬운 말로, 내부 절 번호 없이.
1. Alfred 가 무엇인지 한 줄: 결정은 사용자가, 기록은 Alfred 가
2. **부팅 브리핑** — 세션을 열면 모든 프로젝트의 상태 · 마지막 갱신 · 다음 할 일
3. **프로젝트** — 프로젝트마다 `log.md`(결정과 이유) · `trace/`(일어난 모든 것) · `decision.md`(방향을 정한 판단) · `open.md`(아직 정하지 않은 것)
4. **Incubator** — 구상 중인 아이디어와 간단한 궁금증의 자리. 진짜가 되면 프로젝트로 띄워 카테고리로 옮긴다
5. **"나중에" 할 아이디어** — 말만 하면 `open.md` 에 적어 둔다 (맞는 프로젝트가 없으면 Incubator 의 것)
6. **"저장해"** — 그날 한 일과 결정을 요약하고, 확인을 받은 뒤 log 에 적는다
7. **"X 이어서"** — 프로젝트 X 로 들어가 지금까지의 흐름을 브리핑
8. **일기** — "하루를 정리하자" 하면 trace 로 그날 타임라인을 쓴다
9. **질문 창** — 짧은 선택은 객관식 창으로, 긴 초안은 채팅으로 확인
10. **`/manual-mode`** — 명령 · 코드를 사용자가 직접 친다 / **Archive** — 끝났지만 남겨 둘 것을 브리핑 밖으로

소개 끝에 한 줄로 Incubator 를 시작점으로 권한다: "처음이시라면 Incubator 에서 가볍게 질의응답을 주고받는 걸 추천드릴게요!"
이어서 첫 사용으로 이끈다. 질문 창(Codex 는 request_user_input)으로 한 질문 — 무엇부터 시작할까요? — 선택지는 정확히 둘, 이 순서로
"Incubator 에서 시작하기 (추천)" / "프로젝트 시작하기". Codex 창은 아무도 답하지 않으면 잠시 뒤 저절로 넘어가서 Incubator 를 앞에 둔다.
창의 "직접 입력" 으로 다른 말도 할 수 있다.
답을 받으면 그대로 한다 (사용자가 준 내용으로 프로젝트를 만들거나, Incubator open 항목 · trace 를 시작). 규약이 요구하는 것(objective · code)은 지어내지 말고 묻는다.

## 켜져 있는 동안

훅이 매 턴 팁 규칙을 넣는다. 이번 턴(켜고 끄는 턴)에는 훅이 넣지 않는다.

훅이 넣는 규칙 (요지): 사용자 요청을 먼저 평소대로 하고, 자연스러울 때만 답 끝에 팁 **하나** — "💡 팁: " 으로 시작하는 한 줄,
방금 일과 맞고 이번 세션에 아직 안 알려 준 기능. 맞는 게 없으면 팁 없음. 답마다 하나까지, 작업 · 질문 창 · 초안 · 수동 모드 코드 블록을 끊지 않는다.
팁은 기능 설명이지 사용자의 일에 대한 제안이 아니다. 팁 거리: 아이디어 → Incubator · "나중에" → open · 일이 끝남 → "저장해" ·
방향을 정한 판단 → decision.md · 하루 끝 → "하루를 정리하자" · 있는 프로젝트 얘기 → "X 이어서" · 손으로 하고 싶다 → 수동 모드 ·
끝났지만 남길 것 → Archive · 🔴 neglected · 전체 배경 → "전체 히스토리 봐"
